# Simple Redis Cache

Мінімалістичний WordPress-плагін для двох незалежних рівнів кешування в одному Redis:

- постійний Object Cache API WordPress;
- повносторінковий кеш готового HTML.

Плагін не використовує файловий кеш, не містить реклами, не виконує мініфікацію та не очищає кеш автоматично після зміни контенту.

## Можливості

- TCP, TLS або Unix socket;
- Redis ACL, пароль і вибір Redis database;
- окремий TTL для об'єктів і HTML-сторінок;
- опційне дублювання WordPress transients у базу даних;
- кешування головної, записів, сторінок, CPT, архівів, пошуку та 404;
- виключення за URL, cookie, User-Agent і query-параметрами;
- окремі HTML-варіанти за мовними cookie;
- опційне ізольоване кешування авторизованих користувачів;
- ручне очищення всього кешу або окремого шару;
- ручний прогрів HTML-кешу з живим прогресом для системних сторінок, усіх публічних типів записів і таксономій;
- англомовна й україномовна адмінка відповідно до мови профілю WordPress;
- логічні вкладки для Redis, об'єктного кешу, HTML-кешу, прогріву та діагностики;
- оновлення через публічний GitHub-репозиторій стандартним механізмом WordPress.

## Вимоги

- WordPress 6.5 або новіший;
- PHP 8.1 або новіший;
- розширення PhpRedis;
- один доступний standalone Redis server;
- звичайна single-site інсталяція WordPress — Multisite не підтримується.

## Встановлення

1. Скопіюйте плагін у `wp-content/plugins/simple-redis-cache`.
2. Активуйте **Simple Redis Cache**.
3. Відкрийте **Налаштування → Redis Cache**.
4. На вкладці **Підключення до Redis** вкажіть параметри сервера й збережіть їх.
5. На окремих вкладках увімкніть **Об'єктний кеш**, **Кеш HTML-сторінок** або обидва шари.
6. За потреби виберіть публічні розділи на вкладці **Прогрів кешу** й дочекайтеся завершення прогресу.
7. На вкладці **Стан** перевірте збережене підключення та діагностику.

Для спільного Redis бажано визначити у `wp-config.php` унікальний префікс:

```php
define( 'WP_CACHE_KEY_SALT', 'example.com' );
```

Плагін використовує цю константу як основу префікса для всіх власних Redis-ключів. Решта параметрів Redis задається тільки в адмінці.

## Прогрів і очищення кешу

Вкладка **Прогрів кешу** знаходить головну й сторінку записів, архіви авторів і дат, усі публічні стандартні та кастомні типи записів, а також непорожні терміни всіх публічних таксономій. Доступні джерела вибрані за замовчуванням. Процес виконує анонімні запити у відкритій вкладці та рахує сторінку готовою тільки після підтвердженого Redis `HIT`.

Це ручний прогрів: він не запускається за cron, не очищає попередній кеш і не генерує окремі мовні варіанти, що залежать від cookie. Вкладку потрібно залишити відкритою до завершення.

У верхній панелі WordPress доступне меню **Кешування** з такими діями:

- усього кешу;
- лише HTML-сторінок;
- лише object cache.
- перейти до ручного прогріву HTML-кешу.

Очищення логічне: плагін перемикає покоління ключів і ніколи не виконує `FLUSHDB` або `FLUSHALL`.

## Важливо

- Автоматичного очищення після оновлення записів, термінів, меню чи товарів немає.
- Redis-збої обробляються у fail-open режимі та не повинні робити сайт недоступним.
- Звичайне й примусове перезавантаження браузера не обходить серверний HTML-кеш через `no-cache`, `max-age=0` або `Pragma: no-cache`; `no-store`, Range та умовні HTTP-запити й далі дають bypass.
- Redis credentials зберігаються в базі WordPress і в захищеному generated config для ранніх drop-in.
- Плагін не перезаписує `object-cache.php` або `advanced-cache.php`, якщо ними володіє інший компонент.
- Після деактивації налаштування зберігаються, а власні drop-in видаляються.
- `WP_CACHE` навмисно не видаляється з `wp-config.php`, оскільки його може використовувати інший кеш.

## Оновлення

Оновлення беруться з гілки `master` репозиторію [vitaliikaplia/simple-redis-cache](https://github.com/vitaliikaplia/simple-redis-cache). Щоб опублікувати реліз, потрібно однаково змінити `Version`, `SIMPLE_REDIS_CACHE_VERSION`, `Stable tag` і changelog, оновити файли перекладів, а потім запушити перевірений код у `master`.
